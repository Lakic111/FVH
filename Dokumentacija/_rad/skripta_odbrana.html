1. Velika slika

Šta je DUT

DUT je VHDL IP jezgro ncc_accel, koje smo napravili na PSDS-u. Ono traži šablon u slici normalizovanom unakrsnom korelacijom (NCC). Za svaku poziciju šablona u slici računa NCC² u formatu Q1.31. Vrednost 0x80000000 znači 1,0, tj. savršeno poklapanje. Jezgro ima dva magistralna interfejsa:

  • S00 — AXI4-Lite, kontrolni registri: dimenzije slike i šablona (0x00–0x0C), CTRL (0x30, bit 0 = start) i STATUS (0x34, bit 0 = done_sticky, bit 1 = busy).
  • S01 — AXI4-Full, memorije: slika na +0x00000, šablon na +0x08000, rezultat na +0x10000. Jedan piksel zauzima jednu 32-bitnu reč.

Rad sa jezgrom uvek ide istim redom: upiše se slika i šablon preko S01, upišu se dimenzije preko S00, upiše se CTRL.start, čeka se done_sticky u STATUS, pa se mapa rezultata pročita preko S01. Ceo verifikacioni kod oponaša ovaj tok i proverava ga.

UVM hijerarhija u simulaciji

tb_top  (modul: takt, reset, DUT, interfejsi)
 └─ uvm_test_top        npr. ncc_smoke_test  (bira se sa +UVM_TESTNAME)
     └─ env             ncc_env
         ├─ axil_agent  ncc_axil_agent   ── sqr, drv, mon   → S00
         ├─ axif_agent  ncc_axif_agent   ── sqr, drv, mon   → S01
         ├─ vsqr        ncc_virtual_sequencer (pokazivači na oba sqr)
         ├─ sb          ncc_scoreboard   ← oba monitora
         └─ cov         ncc_coverage     ← oba monitora

Put jedne transakcije

sekvenca ──stavka──► sekvencer ──► drajver ──signali──► DUT
                                                  │
              scoreboard ◄──┬── monitor ◄──signali─┘
              coverage   ◄──┘   (analysis port)

Sekvenca odlučuje šta se radi. Drajver odlučuje kako to izgleda na žicama. Monitor pasivno gleda šta se zaista desilo. Scoreboard proverava da li je rezultat tačan, a coverage beleži šta je isprobano.

2. Zajednički parametri

src/ncc_verif_pkg.sv

Ovaj paket nema klase, samo konstante i tipove izvedene iz RTL-a. Sve ostalo ga uvozi, pa se adrese i širine pišu na jednom mestu.

parameter int S00_ADDR_W = 6;    // max adresa 0x3F
parameter int S01_ADDR_W = 17;   // 128 KB
parameter bit [S00_ADDR_W-1:0] REG_CTRL   = 6'h30;  // upis bit0 = start
parameter bit [S00_ADDR_W-1:0] REG_STATUS = 6'h34;  // samo citanje

typedef enum bit [1:0] {
  REGION_IMG = 2'b00, REGION_TMP = 2'b01, REGION_RESULT = 2'b10, REGION_NONE = 2'b11
} region_e;                          // = bitovi adrese 16:15

parameter int TMP_WORDS = 1024;     // memorija sablona je manja od svog regiona
parameter int MAX_IMG_W = 90, MAX_TMP_W = 30, MAX_TMP_PIX = 900;

typedef enum { ORDER_AW_FIRST, ORDER_W_FIRST, ORDER_SIMUL } aw_w_order_e;
  • region_e odgovara tome kako RTL dekodira adresu: bitovi 16:15 biraju region, a bitovi 14:2 reč.
  • TMP_WORDS = 1024: memorija šablona ima samo 1024 reči, a region je velik 8192 reči. Adrese iznad 1024 se zato „preslikavaju” nazad (aliasing). Scoreboard to mora da zna.
  • aw_w_order_e je najvažniji tip u projektu. AXI dozvoljava da podatak (W) stigne pre adrese (AW), posle nje ili istovremeno. Naš S00 je imao grešku: upis je visio kada W stigne pre AW. Zato svaki upis u okruženju nosi redosled, a mi namerno isprobavamo sva tri.
  • Granice 90/30/900 su ugovor U1–U4 koji jezgro proverava tvrdnjama. Slučajna pobuda mora da ih poštuje.

3. Interfejsi i SVA tvrdnje

src/interfaces/axi_lite_if.sv, src/interfaces/axi_full_if.sv

Interfejs je „snop žica” između SystemVerilog okruženja i VHDL DUT-a. U tb_top se instancira i vezuje na portove DUT-a. Klase do njega dolaze preko virtuelnog interfejsa (pokazivača).

Clocking blokovi

clocking mst_cb @(posedge clk);          // za DRAJVER
  default input #1step output #1ns;
  output awaddr, awvalid, wdata, wstrb, wvalid, bready, ...;
  input  awready, wready, bresp, bvalid, ...;
endclocking

clocking mon_cb @(posedge clk);          // za MONITOR -- samo ulazi
  default input #1step;
  input awaddr, awvalid, awready, wdata, ...;
endclocking
  • input #1step: ulaz se očitava vrednošću koju je signal imao neposredno pre ivice takta, isto kao što bi ga video flip-flop. Tako nema trke između okruženja i DUT-a.
  • output #1ns: drajver menja signal 1 ns posle ivice, pa DUT na sledećoj ivici vidi stabilnu vrednost.
  • Monitor ima zaseban blok koji ima samo ulaze, pa fizički ne može ništa da pobudi.

Protokolske tvrdnje (SVA)

property p_aw_drzi;
  @(posedge clk) disable iff (!rstn)
    awvalid && !awready |=> awvalid && $stable(awaddr);
endproperty
a_aw_drzi: assert property (p_aw_drzi)
  else $error("AXI-Lite S00: AWVALID ili AWADDR promenjen pre AWREADY");

Čita se ovako: „ako je VALID podignut, a READY još nije, onda u sledećem taktu (|=>) VALID mora i dalje biti podignut, a adresa ista ($stable).” To je osnovno AXI pravilo: jednom ponuđena transakcija ne sme se povući ni promeniti. disable iff (!rstn) isključuje proveru tokom reseta. Iste tvrdnje postoje za svih pet kanala.

// Cuva popravku AW/W buga: awready i wready se ne smeju dici istovremeno.
property p_nikad_oba_ready;
  @(posedge clk) disable iff (!rstn) !(awready && wready);
endproperty

Ova tvrdnja je popravka AW/W greške zapisana u izvršnom obliku. Ispravljeni S00 nikad ne podiže oba READY signala u istom taktu. Ako bi se to ikad desilo, greška se vratila. Tvrdnja stoji u interfejsu, pa važi u svakom testu, i u onima koji o njoj ništa ne znaju.

S01 interfejs ima iste tvrdnje i još jednu, specifičnu za pakete:

property p_b_posle_wlast;
  @(posedge clk) disable iff (!rstn)
    $rose(bvalid) |-> $past(wvalid && wready && wlast, 1);
endproperty

Odgovor na upis (BVALID) sme da se pojavi tek kada je primljen poslednji beat paketa (WLAST). $rose hvata trenutak podizanja signala, a $past(..., 1) gleda prethodni takt.

4. Vrh simulacije

tb/tb_top.sv

Ovo je jedini modul u okruženju (sve ostalo su klase). Simulator elaborira njega.

localparam realtime CLK_PERIOD = 10ns;          // 100 MHz, kao na ploci
always #(CLK_PERIOD/2) clk = ~clk;

initial begin                                    // reset 10 taktova
  rstn = 1'b0;  repeat (10) @(posedge clk);  rstn = 1'b1;
end

axi_lite_if #(...) axil_if (.clk(clk), .rstn(rstn));
axi_full_if #(...) axif_if (.clk(clk), .rstn(rstn));

ncc_accel dut ( .s00_axi_awaddr(axil_if.awaddr), ... );   // VHDL DUT

initial begin
  uvm_config_db#(virtual axi_lite_if #(...))::set(null, "*", "axil_vif", axil_if);
  uvm_config_db#(virtual axi_full_if #(...))::set(null, "*", "axif_vif", axif_if);
  run_test();
end

initial begin                                    // nadzorni brojac
  #50ms;  `uvm_fatal("WATCHDOG", "simulacija nije zavrsila na vreme")
end
  • Mešoviti jezik: SystemVerilog modul direktno instancira VHDL entitet ncc_accel. Simulator to podržava ako su oba jezika prevedena u istu biblioteku.
  • uvm_config_db::set ostavlja virtuelni interfejs u globalnoj „bazi” pod imenom axil_vif, odnosno axif_vif. Putanja "*" znači da ga svaka komponenta može preuzeti. Drajveri i monitori ga preuzimaju sa get.
  • run_test() pravi test čije ime dolazi iz argumenta +UVM_TESTNAME=... i pokreće sve UVM faze. Tako se jedan isti snimak simulacije koristi za sve testove.
  • Nadzorni brojač: ako se simulacija zaglavi (na primer vrati se AW/W hang), posle 50 ms prijavljuje fatalnu grešku. Test koji visi ne daje nikakvu informaciju, a test koji padne daje.

5. S00 agent (AXI4-Lite)

src/axil_agent/

Agent je paket od tri komponente koje rade sa jednim interfejsom: sekvencer, drajver i monitor. Ovde ih prolazimo redom, kako ih paket uključuje.

5.1 Sekvencijalna stavka

ncc_reg_item.sv

Stavka je opis jedne transakcije, bez ikakvog znanja o žicama.

class ncc_reg_item extends uvm_sequence_item;
  rand bit [S00_ADDR_W-1:0] addr;
  rand bit [S00_DATA_W-1:0] data;   // kod citanja: drajver upisuje procitano
  rand reg_rw_e             rw;
  rand aw_w_order_e         order;
  rand bit [3:0]            strb;
  rand int unsigned         gap;    // taktova izmedju pokretanja dva kanala
  bit [1:0] resp;                   // BRESP / RRESP, popunjava drajver

  constraint c_order  { order dist { ORDER_AW_FIRST := 2, ORDER_W_FIRST := 2,
                                     ORDER_SIMUL := 1 }; }
  constraint c_gap    { order == ORDER_SIMUL -> gap == 0;
                        order != ORDER_SIMUL -> gap inside {[1:4]}; }
  constraint c_addr   { soft addr inside { REG_IMG_W, ..., REG_STATUS }; }
  constraint c_status { addr == REG_STATUS -> rw == REG_READ; }

  `uvm_object_utils_begin(ncc_reg_item)
    `uvm_field_int(addr, UVM_ALL_ON) ...
  `uvm_object_utils_end
  • rand polja se biraju slučajno pozivom randomize(), uz poštovanje ograničenja.
  • dist daje težine: redosledi AW-prvi i W-prvi biraju se dvostruko češće od istovremenog.
  • -> je implikacija: ako su kanali istovremeni, razmak mora biti 0, a inače je od 1 do 4 takta.
  • soft ograničenje je „podrazumevano”: sekvenca ga može pregaziti (na primer upisom u neiskorišćeni registar) bez pada randomizacije.
  • STATUS se samo čita, pa ograničenje ne dozvoljava upis u njega.
  • Makroi `uvm_object_utils i `uvm_field_* registruju klasu u fabrici (da radi type_id::create) i daju gotove print, copy i compare.

5.2 Sekvencer

ncc_axil_sequencer.sv
class ncc_axil_sequencer extends uvm_sequencer #(ncc_reg_item);
  `uvm_component_utils(ncc_axil_sequencer)
  ...
endclass

Sekvencer nema svoju logiku. On je „red čekanja” između sekvence i drajvera: sekvenca mu predaje stavke, a drajver ih uzima jednu po jednu. Parametrizovan je tipom stavke, pa prihvata samo ncc_reg_item.

5.3 Drajver

ncc_axil_driver.sv
function void build_phase(uvm_phase phase);
  if (!uvm_config_db#(virtual axi_lite_if #(...))::get(this, "", "axil_vif", vif))
    `uvm_fatal("NOVIF", "axil_vif nije nadjen u uvm_config_db")
endfunction

task run_phase(uvm_phase phase);
  idle();                                   // svi VALID = 0
  wait (vif.rstn === 1'b1);
  forever begin
    seq_item_port.get_next_item(req);       // blokira dok sekvenca ne posalje
    if (req.rw == REG_WRITE) drive_write(req);
    else                     drive_read(req);
    seq_item_port.item_done();              // javlja sekvenci da je gotovo
  end
endtask

Ovo je standardna petlja drajvera. get_next_item čeka stavku, item_done javlja sekvenci da je stavka izvršena. Tek tada se sekvenci vraća finish_item, pa sekvenca u stavci već vidi pročitani podatak.

task drive_write(ncc_reg_item it);
  case (it.order)                      // kasnjenje svakog kanala
    ORDER_AW_FIRST: begin aw_kasnjenje = 0;      w_kasnjenje = it.gap; end
    ORDER_W_FIRST:  begin aw_kasnjenje = it.gap; w_kasnjenje = 0;      end
    default:        begin aw_kasnjenje = 0;      w_kasnjenje = 0;      end
  endcase
  fork
    begin : kanal_aw
      repeat (aw_kasnjenje) @(vif.mst_cb);
      vif.mst_cb.awaddr  <= it.addr;
      vif.mst_cb.awvalid <= 1'b1;
      do @(vif.mst_cb); while (vif.mst_cb.awready !== 1'b1);   // rukovanje
      vif.mst_cb.awvalid <= 1'b0;
    end
    begin : kanal_w  ... end               // isto za W
    begin : kanal_b
      vif.mst_cb.bready <= 1'b1;
      do @(vif.mst_cb); while (vif.mst_cb.bvalid !== 1'b1);
      it.resp = vif.mst_cb.bresp;
      vif.mst_cb.bready <= 1'b0;
    end
  join
endtask

Ključni deo celog okruženja. Tri AXI kanala (AW, W, B) vode se kao tri paralelne niti (fork … join), jer su i u AXI-ju nezavisni. Zbog toga drajver može da pošalje W pre AW, sa razmakom od gap taktova, a to je upravo scenario koji je ranije obarao S00. Petlja do … while (ready) je AXI rukovanje: VALID ostaje gore dok slave ne odgovori READY-jem. join čeka sve tri niti. Čitanje radi isto, sa dva kanala (AR i R).

5.4 Monitor

ncc_axil_monitor.sv

Monitor ne pobuđuje ništa. Posmatra interfejs kroz mon_cb i od signala rekonstruiše transakcije. Ima pet paralelnih niti, po jednu za svaki kanal:

task run_phase(uvm_phase phase);
  wait (vif.rstn === 1'b1);
  fork  prati_aw();  prati_w();  prati_b();  prati_ar();  prati_r();  join
endtask

task prati_aw();
  forever begin
    @(vif.mon_cb);
    if (vif.mon_cb.awvalid === 1'b1 && !prethodni) t_postavljen = $time;  // VALID se upravo podigao
    prethodni = (vif.mon_cb.awvalid === 1'b1);
    if (vif.mon_cb.awvalid === 1'b1 && vif.mon_cb.awready === 1'b1)
      aw_q.push_back('{addr: vif.mon_cb.awaddr, t: t_postavljen});        // rukovanje
  end
endtask
  • Svaki obavljen AW i W ide u svoj red (aw_q, w_q), zajedno sa trenutkom kada je VALID podignut.
  • Upis se sklapa tek na rukovanju kanala B (prati_b). Tada su i adresa i podatak sigurno primljeni, pa se iz oba reda uzima po jedan element.
  • Redosled se računa poređenjem vremena: aw.t < w.t daje AW_FIRST, aw.t > w.t daje W_FIRST, a jednaka vremena daju SIMUL. Meri se po podizanju VALID-a, a ne po rukovanju, jer popravljeni S00 uvek prvo prihvata AW, pa bi po rukovanju svaki upis izgledao kao „AW prvi”.
  • Ako stigne B bez para AW/W, monitor prijavljuje kršenje AXI protokola.
  • Gotova stavka se šalje dalje sa ap.write(it). To je analysis port, na koji su vezani scoreboard i coverage.

5.5 Konfiguracija i agent

ncc_axil_agent_config.sv, ncc_axil_agent.sv
function void build_phase(uvm_phase phase);
  if (!uvm_config_db#(ncc_axil_agent_config)::get(this, "", "cfg", cfg))
    cfg = ncc_axil_agent_config::type_id::create("cfg");   // podrazumevano: UVM_ACTIVE
  mon = ncc_axil_monitor::type_id::create("mon", this);    // monitor UVEK
  if (cfg.is_active == UVM_ACTIVE) begin
    sqr = ncc_axil_sequencer::type_id::create("sqr", this);
    drv = ncc_axil_driver   ::type_id::create("drv", this);
  end
endfunction

function void connect_phase(uvm_phase phase);
  mon.ap.connect(ap);                                     // port monitora ide napolje
  if (cfg.is_active == UVM_ACTIVE)
    drv.seq_item_port.connect(sqr.seq_item_export);       // drajver <- sekvencer
endfunction

Aktivan agent pobuđuje magistralu (ima drajver i sekvencer). Pasivan agent ima samo monitor i služi za posmatranje, na primer kada bi isti agent gledao magistralu u većem sistemu gde nju vodi procesor. To je ponovna upotrebljivost komponenti.

5.6 Sekvence S00 agenta

sequences/ncc_axil_base_seq.sv, sequences/ncc_reg_rw_seq.sv
task upisi(bit [5:0] a, bit [31:0] d, aw_w_order_e o = ORDER_AW_FIRST, int unsigned g = 1);
  ncc_reg_item it = ncc_reg_item::type_id::create("it");
  start_item(it);                                    // trazi dozvolu od sekvencera
  ok = it.randomize() with { addr == a; data == d; rw == REG_WRITE; order == o; gap == g; };
  finish_item(it);                                   // predaje drajveru i ceka item_done
endtask

Ovo je obrazac koji se ponavlja u svim sekvencama: create, pa start_item, pa randomize() with {…} (fiksiramo ono što nam treba, ostalo je slučajno), pa finish_item. ncc_reg_rw_seq ovim zadacima upiše registar, pročita ga i uporedi, nad četiri registra dimenzija i u sva tri redosleda.

6. S01 agent (AXI4-Full)

src/axif_agent/

Raspored je isti kao kod S00 (stavka, sekvencer, drajver, monitor, konfiguracija, agent, sekvence). Ovde su opisane samo razlike, koje sve potiču od toga što AXI4-Full prenosi pakete (burst-ove) od više reči.

6.1 Stavka

ncc_mem_item.sv
rand region_e     region;
rand bit [12:0]   word;          // indeks reci u regionu (addr[14:2])
rand int unsigned len;           // broj beat-ova = AWLEN + 1
rand bit [31:0]   data[];        // dinamicki niz, len elemenata

constraint c_len   { len inside {[1:256]};  data.size() == len; }
constraint c_4k    { ((word * 4) % 4096) + (len * 4) <= 4096; }
constraint c_opseg { word + len <= 8192; }

function bit [16:0] puna_adresa();  return {region, word, 2'b00};  endfunction
  • c_len: AXI paket ima najviše 256 beat-ova, a niz podataka mora imati tačno len elemenata.
  • c_4k: AXI zabranjuje da paket pređe granicu od 4 KB.
  • puna_adresa() spaja region, reč i dva nulta bita (poravnanje na 4 bajta) u 17-bitnu adresu, isto kako je RTL rastavlja.

6.2 Drajver

ncc_axif_driver.sv
begin : kanal_w
  repeat (w_kasnjenje) @(vif.mst_cb);
  for (int i = 0; i < it.len; i++) begin
    vif.mst_cb.wdata  <= it.data[i];
    vif.mst_cb.wlast  <= (i == it.len - 1);        // poslednji beat
    vif.mst_cb.wvalid <= 1'b1;
    do @(vif.mst_cb); while (vif.mst_cb.wready !== 1'b1);
  end
  vif.mst_cb.wvalid <= 1'b0;
end

Isti fork sa tri kanala kao kod S00, samo što W kanal šalje len beat-ova i podiže WLAST na poslednjem. Adresni kanal šalje AWLEN = len-1, AWSIZE = 4 bajta i AWBURST = INCR (adresa raste). Čitanje prima beat-ove dok ne skupi len reči.

6.3 Monitor

ncc_axif_monitor.sv

Beat-ove sa W kanala skuplja u bafer. Na rukovanju B kanala uzima adresu iz reda AW, proverava da je broj primljenih beat-ova jednak AWLEN+1 i od toga pravi jednu stavku za ceo paket. Za čitanje skuplja R beat-ove dok ne vidi RLAST. Ako svi beat-ovi paketa nemaju isti WSTRB, izdaje upozorenje.

6.4 Sekvence S01 agenta

ncc_axif_base_seq daje upisi_blok() i procitaj_blok(). ncc_mem_blok_seq upiše blok, pročita ga i uporedi, sa dužinama 1, 2, 3, 8 i 16 beat-ova, u regionima slike i šablona i u sva tri redosleda. Memorija čuva samo donjih 8 bita piksela, pa se poredi poslato & 0xFF.

7. Referentni model

src/ref_model/ncc_ref_pkg.sv

Referentni model je „druga, nezavisna implementacija” istog algoritma, napisana bihevioralno u SystemVerilog-u. Scoreboard poredi DUT sa njim. Model je bit-tačan: koristi iste širine, isto zaokruživanje i isti format kao RTL, pa se poređenje radi sa !==, bez tolerancije.

Za svaku poziciju (u, v) šablona u slici računa se:

NCC²(u,v) = ( Σ df·dt )² / ( Σ df² · Σ dt² ),   gde je df = f − f̄  i  dt = t − t̄

f je piksel slike ispod šablona, t je piksel šablona, a f̄ i t̄ su njihove srednje vrednosti.

t_mean = 8'(( sum_t + (count / 2) ) / count);          // srednja vrednost sablona, zaokruzena
for (v ...) for (u ...) begin
  f_bar = 8'(( sum_f + (count / 2) ) / count);         // srednja vrednost prozora
  ...
  bit signed [8:0]  df = 9'(slika[...])  - 9'(f_bar);   // razlika, 9 bita sa znakom
  bit signed [8:0]  dt = 9'(sablon[...]) - 9'(t_mean);
  bit signed [17:0] p_num = df * dt;                     // proizvodi kao u RTL-u
  sum_num += p_num;  sum_den_f += 26'(df*df);  sum_den_t += 26'(dt*dt);
  ...
  if (sum_den_f == 0 || sum_den_t == 0) rezultat = 0;   // ravan prozor ili sablon
  num_sq   = sum_num * sum_num;
  den_prod = sum_den_f * sum_den_t;
  kolicnik = (83'(num_sq) << 31) / 83'(den_prod);       // pomeranje za 31 = format Q1.31
  rezultat[v * res_w + u] = kolicnik[31:0];
end
  • Srednje vrednosti se zaokružuju (+ count/2) i skraćuju na 8 bita, kao u RTL-u.
  • Kvadriranjem brojioca nestaje znak, pa je NCC² uvek između 0 i 1.
  • Pomeranje za 31 bit pre deljenja daje format Q1.31, pa 1,0 postaje 0x80000000.
  • Kada je imenilac 0 (svi pikseli isti), rezultat je 0, isto kao u jezgru.

8.2 Scoreboard

ncc_scoreboard.sv

Scoreboard sluša isključivo monitore. Ne zna ništa o sekvencama ni drajverima, i sve što zna vidi na magistrali. Radi u četiri koraka:

// 1. i 2. -- ulaz sa S00: pamti dimenzije, na start racuna predikciju
function void write_reg(ncc_reg_item t);
  if (t.rw == REG_WRITE) case (t.addr)
    REG_IMG_W: img_w = t.data[7:0];    ...
    REG_CTRL:  if (t.data[CTRL_START_BIT]) pokreni();
  endcase
  else if (t.addr == REG_STATUS && t.data[STATUS_DONE_BIT]) video_done = 1'b1;
endfunction

// ulaz sa S01: upisi pune senku memorije, citanja rezultata se porede
function void write_mem(ncc_mem_item t);
  if (t.rw == MEM_WRITE) begin
    if (!t.strb[0]) return;          // RTL: mem_we <= wr_beat and WSTRB(0)
    case (t.region)
      REGION_IMG: foreach (t.data[i]) senka_slika[t.word + i] = t.data[i][7:0];
      REGION_TMP: foreach (t.data[i]) senka_sablon[(t.word + i) % TMP_WORDS] = t.data[i][7:0];
      REGION_RESULT: ;                  // samo citanje -- upis se zanemaruje
    endcase
  end else if (t.region == REGION_RESULT) uporedi(t);
endfunction
  • Senka memorije (senka_slika, senka_sablon) je asocijativni niz: kopija onoga što bi trebalo da bude u memoriji DUT-a, sastavljena iz viđenih upisa.
  • strb[0]: RTL upisuje u memoriju samo kada je bit 0 signala WSTRB postavljen, pa senka mora da se ponaša isto.
  • % TMP_WORDS: memorija šablona ima 1024 reči, pa se veće adrese preslikavaju (aliasing).
// 3. -- predikcija
protected function void pokreni();
  ... slika/sablon se prepisuju iz senke (nepoznato = 0) ...
  ncc_predikcija(img_w, img_h, tmp_w, tmp_h, slika, sablon, mapa);   // referentni model
  foreach (mapa[i]) predikcija[i] = mapa[i];
endfunction

// 4. -- poredjenje svake procitane reci rezultata
foreach (t.data[i]) begin
  idx = t.word + i;

    br_gresaka++;

  end
end

// zavrsna provera
function void check_phase(uvm_phase phase);
  if (br_poredjenja == 0) `uvm_error("SB", "scoreboard nije izvrsio nijedno poredjenje")
endfunction

check_phase je zaštita od „lažnog prolaza”. Scoreboard koji ništa nije uporedio nije dokaz ispravnosti, pa se to prijavljuje kao greška.

8.3 Coverage

ncc_coverage.sv

Funkcionalna pokrivenost odgovara na pitanje da li smo isprobali sve što smo planirali. Odvojena je od scoreboard-a: jedna komponenta proverava tačnost, a druga potpunost. Vezana je na iste monitore.

covergroup cg_dimenzije with function sample(int unsigned iw, ih, tw, th);
  cp_img_w: coverpoint iw { bins min = {1}; bins ispod = {[2:44]}; bins coarse = {45};
                           bins iznad = {[46:89]}; bins max = {90}; }
  ...
  x_img_tmp: cross cp_img_w, cp_tmp_w {
    ignore_bins nemoguce_min = binsof(cp_img_w.min) && !binsof(cp_tmp_w.min);
  }
endgroup

covergroup cg_kontrola with function sample(bit start, busy, done);
  x_start_busy: cross cp_start, cp_busy;     // (1,1) = start dok jezgro radi, test T7
  x_start_done: cross cp_start, cp_done;
endgroup

covergroup cg_axi with function sample(aw_w_order_e ord, cov_region_e reg_o, ...);
  x_order_region: cross cp_order, cp_region;  // sredisnji cilj: AW/W redosled u svakom regionu
  cp_len:  coverpoint blen { bins b1={1}; bins b2={2}; bins b3_15={[3:15]}; ... bins b256={256}; }
  cp_strb: coverpoint strb { bins puna={4'hF}; bins b1={4'h1}; ... }
endgroup
  • Bin-ovi dele opseg na zanimljive klase: granice (1, 90), sredinu i „grubu” veličinu 45 (pola segmenta table, koju koristi aplikacija).
  • cross traži da se svaka kombinacija pojavi. Najvažniji je redosled × region: AW/W greška se proverava u svakom memorijskom regionu i u registrima.
  • ignore_bins izbacuje kombinacije koje su nemoguće po ugovoru U4 (šablon ne sme biti veći od slike). Bez toga bi 100% bilo nedostižno.
  • sample() se poziva ručno. Dimenzije se uzorkuju u trenutku upisa u CTRL, kada su stvarno u upotrebi, a ne pri svakom upisu dimenzije.

12. Moguća pitanja na odbrani

1. Zašto scoreboard sluša monitor, a ne drajver?

Drajver zna šta je hteo da pošalje, a monitor vidi šta se stvarno desilo na magistrali. Kada bi scoreboard verovao drajveru, greška u drajveru ili protokolu ostala bi nevidljiva. Isto tako, senka memorije u scoreboard-u nastaje samo iz viđenih upisa.

2. Kako znate da scoreboard zaista nešto proverava?

Iz tri razloga. Prvo, check_phase prijavljuje grešku ako nije bilo nijednog poređenja. Drugo, ispisuje se broj poređenja (ukupno 3106 u regresiji). Treće, uradili smo negativnu proveru: kada smo namerno pokvarili upisni put u drajveru (wdata ^ 1), testovi su pali. Provera koja ne ume da padne ništa ne dokazuje.

3. Kako je u okruženju pokrivena AW/W greška?

Na četiri mesta. U stavci postoji polje order. Drajver vodi AW i W kao paralelne niti, pa može da pošalje W pre AW. Monitor meri redosled na samoj magistrali. Coverage ima ukrštanje redosled × region, pa je redosled proveren u svakom regionu. Uz to SVA tvrdnja !(awready && wready) u interfejsu čuva popravku u svakom testu.

4. Šta je virtuelni sekvencer i zašto vam treba?

Scenario rada sa jezgrom koristi obe magistrale (slika preko S01, start preko S00). Virtuelni sekvencer drži pokazivače na oba prava sekvencera, pa jedna virtuelna sekvenca može da šalje stavke na oba.

5. Zašto referentni model, a ne unapred izračunati golden fajlovi?

Slučajni test svaki put pravi druge podatke i dimenzije, pa bi za golden fajlove trebalo unapred izračunati rezultat za svaki mogući ulaz. Referentni model računa predikciju tokom simulacije, za bilo koji ulaz. Bit-tačan je, pa se poredi bez tolerancije.

6. Šta znači 0x80000000?

NCC² u formatu Q1.31 (1 celobrojni bit i 31 razlomački). 0x80000000 je 1,0, tj. savršeno poklapanje šablona i prozora. Zato se skorovi porede kao neoznačeni brojevi, jer bi kao označeni bili negativni.

7. Šta je clocking blok i čemu služi?

Određuje kada okruženje čita i piše signale u odnosu na takt. Ulazi se čitaju neposredno pre ivice (#1step), a izlazi se menjaju 1 ns posle nje. Tako nema trke između okruženja i DUT-a, a ponašanje je isto u svakom simulatoru.

8. Šta je objection?

Mehanizam za kraj run_phase. Test podigne prigovor pre sekvence i spusti ga posle nje. Faza se završava kada niko ne drži prigovor. Bez toga bi simulacija stala u trenutku 0.

9. Čemu služi fork … join_any sa disable fork?

Čekanje na done_sticky ide paralelno sa čuvarom vremena. Koja god nit prva završi, druga se ubija. Ako jezgro visi, test padne sa jasnom porukom umesto da se regresija zaglavi.

10. Šta je aktivan, a šta pasivan agent?

Aktivan agent ima sekvencer, drajver i monitor i pobuđuje magistralu. Pasivan ima samo monitor i samo posmatra. Bira se kroz konfiguraciju (is_active). Pasivan bi služio kada isti agent posmatra magistralu u većem sistemu.

11. Zašto ignore_bins u coverage-u?

Neke kombinacije su nemoguće po ugovoru U4: šablon ne sme biti veći od slike. Ako se ne izbace, pokrivenost nikad ne može doći do 100%, a 100% onda ne bi ništa značilo. Svaki isključeni bin ima obrazloženje.

12. Šta je seed i zašto 20 seed-ova?

Seed je početna vrednost generatora slučajnih brojeva. Svaki daje drugi, ali ponovljiv scenario. Više seed-ova znači više različitih ulaza. Jedna greška u pobudi (paket duži od 256 beat-ova) pojavila se tek na 6 od 20 seed-ova, a sa jednim seed-om ne bi bila primećena.

13. Šta je donela simulacija u dva simulatora?

Ceo SV/UVM kod preveo se u Xcelium-u iz prvog pokušaja. Xcelium je, međutim, odbio tri konstrukcije u Xilinx AXI šablonu DUT-a koje XSim prećutno prihvata (AGNLSC, CSODAS, TRRANGEC). Rešene su opcijom -relax, izmenom jednog reda u kopiji DUT-a i podešavanjem u xrun_run.tcl. Sa jednim simulatorom ništa od toga ne bi se videlo.

14. Zašto u scoreboard-u stoji % TMP_WORDS i provera strb[0]?

Scoreboard mora da modeluje memoriju tačno kao RTL. Memorija šablona ima 1024 reči, pa se veće adrese preslikavaju na početak. RTL upisuje samo kada je WSTRB(0)=1. Kada senka ne bi radila isto, scoreboard bi prijavljivao lažne greške.

15. Zašto je svaka klasa u posebnom fajlu, a paket samo uključuje?

Zbog preglednosti i ponovne upotrebe: agent se može uzeti zasebno i fajl odgovara klasi. SystemVerilog paket je i dalje jedna celina za prevođenje, a `include samo lepi fajlove u njega, po redosledu zavisnosti.
